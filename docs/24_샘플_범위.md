# 샘플 범위

## 1. 문서 목적

이 문서는 블루점프 팬 커뮤니티 샘플에서 구현할 기능과 구현하지 않을 기능의 범위를 정의합니다.

이번 샘플은 블루점프 측에 서비스의 구조, UI 방향, 주요 사용자 경험을 제안하기 위한 비공식 Concept Sample입니다.

실제 운영 가능한 서비스를 만드는 단계가 아니므로 **Frontend와 Mock Data만으로 구성**하며, Database와 Backend는 구축하지 않습니다.

공식 협업이 이루어진 이후 실제 요구사항을 다시 협의하고 MVP의 기능 및 기술 범위를 별도로 정의합니다.

---

## 2. 샘플 개발 원칙

### 2.1 Frontend만 구현합니다

샘플에서는 다음 영역만 구현합니다.

- 화면
- Layout
- Navigation
- Responsive UI
- 버튜버별 Theme
- Animation
- 사용자 Interaction
- Mock Data 기반 콘텐츠
- Client State를 이용한 Demo Interaction

다음 영역은 구축하지 않습니다.

- Database
- Backend API
- Server Action
- 실제 Authentication
- 실제 OAuth
- 실제 결제 및 정산
- 실제 외부 플랫폼 API 연동
- 운영용 관리자 시스템

---

### 2.2 모든 서비스 데이터는 Mock Data를 사용합니다

샘플에서 표시되는 데이터는 프로젝트 내부에 정의한 Mock Data를 사용합니다.

예:

- 버튜버
- 사용자
- 게시글
- 댓글
- Reaction
- 팬아트 및 기타 창작물
- 프로젝트
- 오프라인 모임
- 일정
- 팬덤 아카이브
- 활동 이력
- 포인트
- 이모티콘

실제 데이터 저장이나 조회는 수행하지 않습니다.

---

### 2.3 필요한 동작은 Client State로 표현합니다

사용자 경험을 확인하는 데 필요한 간단한 상태 변경은 Frontend 내부에서 처리할 수 있습니다.

예:

```text
Reaction 클릭
→ 숫자 및 선택 상태 변경

프로젝트 참여
→ 참여 상태로 변경

Demo 로그인
→ 현재 사용자 변경

감옥 복귀 절차 완료
→ 일반 사용자 상태로 변경

이모티콘 구매
→ 구매 완료 상태 표시
```

이러한 상태는 실제 서버에 저장되지 않으며 새로고침 시 초기 상태로 돌아가도 됩니다.

---

### 2.4 운영 정책은 확정하지 않습니다

샘플에서 표현되는 기능이 실제 운영 정책을 의미하지는 않습니다.

다음 항목은 공식 협업 이후 별도로 논의합니다.

- 회원 정책
- 버튜버 및 운영자 권한
- 제재 기준
- 영구 차단 기준
- 오프라인 모임 정책
- 미성년자 관련 정책
- 팬 창작물 이용 정책
- 개인정보 처리
- 포인트 정책
- 결제 및 환불
- 창작자 정산

## 3. 주요 샘플 흐름

샘플에서는 다음 사용자 흐름을 우선적으로 구현합니다.

### 3.1 서비스 진입

```text
사이트 접속
↓
Portal Layer
↓
PRESS SPACE TO JUMP
↓
Portal Animation
↓
메인 페이지
```

### 3.2 버튜버 커뮤니티 탐색

```text
메인 페이지
↓
버튜버 선택
↓
버튜버별 Theme 전환
↓
버튜버 커뮤니티
↓
게시글 및 콘텐츠 탐색
```

### 3.3 팬 프로필 탐색

```text
게시글 또는 창작물
↓
작성자 선택
↓
프로필
↓
활동 유형
↓
창작물 및 활동 이력
```

### 3.4 창작물 탐색

```text
창작
↓
창작물 목록
↓
창작물 상세
↓
작성자 프로필
```

### 3.5 팬 프로젝트 탐색

```text
프로젝트
↓
프로젝트 상세
↓
모집 역할
↓
참여자 및 진행 상태
```

### 3.6 오프라인 모임 탐색

```text
모임
↓
모임 상세
↓
일정 / 장소 / 주최자 / 참가 현황
```

# 4. Portal Layer

서비스 진입 시 메인 페이지 위에 Portal Layer를 표시합니다.

### 구현 범위

- [ ] 메인 페이지 위에 전체 화면 Portal Layer를 표시합니다.
- [ ] 블루점프 Portal Visual을 구성합니다.
- [ ] PC에서는 Space 입력으로 진입할 수 있도록 합니다.
- [ ] Pointer 입력도 지원합니다.
- [ ] 모바일 및 태블릿에서는 Touch 입력을 지원합니다.
- [ ] Portal Open Animation을 제공합니다.
- [ ] Animation 종료 후 뒤에 있던 메인 페이지가 자연스럽게 나타나도록 합니다.
- [ ] `prefers-reduced-motion`을 고려합니다.
- [ ] Animation을 생략할 수 있는 수단을 고려합니다.

다음 요소는 샘플에서 반드시 확정하지 않습니다.

- 재방문 시 Portal 노출 정책
- Portal 노출 기록 저장 방식
- 로그인 상태에 따른 차이
- 방송 상태와 Portal Effect 연동
- 계절 및 이벤트별 Portal

# 9. 팬 활동 유형

회원 활동량을 기준으로 한 수직적인 등급 대신 사용자가 어떤 활동을 하는지 표현할 수 있는 유형을 사용합니다.

예:

- Artist
- Meme Maker
- Clip Maker
- Video Creator
- Musician
- 3D Artist
- Designer
- Developer
- Archivist
- Organizer
- Guide

### 구현 범위

- [ ] 한 사용자에게 여러 활동 유형을 표시합니다.
- [ ] 프로필에서 활동 유형을 확인할 수 있도록 합니다.
- [ ] 활동 유형별로 서로 다른 시각적 표현을 적용합니다.

유형의 획득 조건이나 검증 방식은 구현하지 않습니다.

# 10. 팬 프로필 카드

사용자의 기본 정보와 팬덤 활동을 하나의 프로필로 보여 줍니다.

내부적으로는 장기적인 `Fan Passport` 개념을 고려합니다.

### 표시 항목 후보

- 프로필 이미지
- 닉네임
- 관심 버튜버
- 활동 유형
- 주요 창작물
- 참여 프로젝트
- 활동 이력
- 가입 시기
- Profile Decoration

### 구현 범위

- [ ] 사용자 프로필 화면
- [ ] 프로필 요약 카드
- [ ] 활동 유형
- [ ] 창작물
- [ ] 프로젝트 참여 이력

장기적으로 프로필 카드를 실물 굿즈로 제작하는 방안을 고려할 수 있습니다.

예:

- PVC Card
- 버튜버별 Theme Card
- 이벤트 한정 디자인
- Hologram Card
- QR 또는 NFC를 통한 Web Profile 연결

실물 제작 및 판매 기능은 샘플에서 구현하지 않습니다.

# 15. 감옥 Demo

커뮤니티 활동 제한 상태를 별도의 감옥 화면으로 표현합니다.

### 구현 범위

- [ ] Detained 상태의 Demo User
- [ ] 감옥 화면
- [ ] 남은 제한 시간
- [ ] 제한 안내
- [ ] 복귀 Interaction

대표적인 Demo Flow는 다음과 같이 구성할 수 있습니다.

```text
죄송합니다
↓
죄송합니다
↓
죄송합니다
↓
일반 상태 복귀
```

모든 과정은 Client State에서만 동작합니다.

다음 기능은 구현하지 않습니다.

- Detained User

# 23. 배포

샘플은 Frontend Application 형태로 배포합니다.

블루점프 측에서는 별도의 계정 생성이나 설치 없이 배포된 URL에 접속하여 샘플을 직접 확인할 수 있도록 합니다.

샘플 환경에서는 실제 개인정보, 결제 정보 또는 운영 데이터를 입력받지 않습니다.

# 24. 완료 기준

샘플의 완료 여부는 실제 서비스 기능의 완성도가 아니라 주요 제안 내용을 직접 탐색할 수 있는지를 기준으로 판단합니다.

최소한 다음 흐름을 확인할 수 있어야 합니다.

1. Portal을 통해 메인 페이지로 진입할 수 있습니다.
2. 메인 페이지에서 주요 커뮤니티 영역을 확인할 수 있습니다.
3. 버튜버별 커뮤니티로 이동할 수 있습니다.
4. 버튜버에 따라 Theme이 변경됩니다.
5. 게시글과 팬 창작물을 탐색할 수 있습니다.
6. 사용자 프로필에서 활동 유형과 활동 이력을 확인할 수 있습니다.
7. 프로젝트의 모집 및 참여 구조를 확인할 수 있습니다.
8. 오프라인 모임이 어떤 형태로 제공되는지 확인할 수 있습니다.
9. 팬덤 아카이브의 기본 형태를 확인할 수 있습니다.
10. 주요 화면을 Desktop과 Mobile에서 탐색할 수 있습니다.

# 25. 샘플 이후

공식 협업이 이루어질 경우 샘플에서 사용한 기능과 정책을 그대로 실제 서비스 요구사항으로 확정하지 않습니다.

블루점프 측과 다시 협의하여 다음 내용을 정식으로 정의합니다.

- MVP 범위
- 요구사항
- 정보 구조
- 사용자 흐름
- 화면 설계
- 인증
- Database
- Backend
- 권한
- 운영 정책
- Moderation
- 개인정보
- 보안
- 외부 플랫폼 연동
- 포인트 및 결제
- 관리자 시스템

샘플의 Frontend Component와 Design System 중 실제 서비스에도 적합한 부분은 재사용할 수 있으며, 서비스 로직과 Backend 구조는 확정된 요구사항을 기준으로 새롭게 설계합니다.
