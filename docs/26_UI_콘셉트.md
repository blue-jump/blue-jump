# UI 콘셉트

## 1. 문서 목적

이 문서는 블루점프 팬 커뮤니티 샘플의 전반적인 UI 방향을 정의합니다.

샘플의 목적은 완성된 브랜드 가이드나 Design System을 구축하는 것이 아니라, 다음 내용을 일관된 화면으로 표현하는 것입니다.

- 블루점프 전체 커뮤니티의 공통 정체성
- 각 버튜버별 개별 정체성
- 팬들이 모이고 활동하는 커뮤니티의 분위기
- 창작, 프로젝트, 모임 등 다양한 활동의 연결
- Portal을 통한 서비스 진입 경험

구체적인 Component 규격, Design Token 값, Typography Scale 등은 실제 화면 설계 및 구현 과정에서 조정합니다.

---

## 2. 기본 UI 콘셉트

샘플의 기본 UI 콘셉트는 다음과 같이 정의합니다.

> **Portal Pop / Digital Plaza**

서로 다른 버튜버와 팬들이 하나의 Portal을 통해 연결되고, 여러 활동이 동시에 이루어지는 디지털 광장을 표현합니다.

UI는 지나치게 미래적이거나 게임처럼 구성하지 않고, 일반적인 웹 커뮤니티의 사용성을 유지하면서 블루점프만의 시각적 특징과 놀이성을 일부 추가합니다.

---

## 3. 디자인 방향

전체 UI는 다음 성격을 기준으로 구성합니다.

### 밝고 개방적

커뮤니티의 기본 공간은 폐쇄적인 Dark UI보다 밝고 넓은 인상을 우선합니다.

콘텐츠와 사용자 이미지가 화면의 중심이 될 수 있도록 배경과 기본 Surface는 비교적 중립적으로 구성합니다.

---

### 유동적

블루점프의 `Jump`, `Portal`, 연결이라는 이미지를 UI와 Motion에 반영합니다.

다만 장식과 Animation이 실제 사용성을 방해하지 않도록 제한적으로 사용합니다.

---

### 팬덤의 놀이성

기업 홈페이지처럼 지나치게 정적인 화면보다 팬들이 직접 활동하는 공간이라는 느낌을 제공합니다.

다음 요소에서 가벼운 놀이성을 사용할 수 있습니다.

- Profile Decoration
- 활동 유형
- Reaction
- Portal
- Talent Theme
- 이모티콘
- 감옥 Demo

---

### 콘텐츠 중심

팬아트, 영상, 밈 등 팬 콘텐츠가 UI 장식보다 우선합니다.

특히 Creative 영역에서는 화면 장식을 최소화하여 작품 자체가 가장 먼저 보이도록 합니다.

---

## 4. 시각적 계층

서비스의 시각적 정체성은 세 단계로 나눕니다.

```text
Blue Jump Foundation
        ↓
Talent Theme
        ↓
User Expression
```

### Blue Jump Foundation

서비스 전체에서 유지되는 공통 UI입니다.

- 기본 Layout
- Typography
- Navigation
- Surface
- 공통 Component
- 기본 Motion
- Blue / Cyan 계열의 Brand Color

### Talent Theme

각 버튜버 공간에서 변경되는 영역입니다.

- Primary Color
- Accent Color
- Hero Visual
- 배경 장식
- 일부 Component 강조색
- 일부 Motion Effect

### User Expression

사용자가 직접 자신의 정체성을 표현하는 영역입니다.

- Profile Card
- 활동 유형
- Profile Decoration
- 이모티콘
- 관심 버튜버
- 활동 이력

이 세 계층을 분리하여 버튜버별 Theme이나 사용자 장식이 서비스 전체 UI의 일관성을 해치지 않도록 합니다.

---

# 5. 기본 색상 방향

전체 화면을 Blue 계열로 채우기보다 Blue를 **연결과 Interaction을 나타내는 색상**으로 사용합니다.

기본적인 구성은 다음과 같습니다.

```text
Neutral Background
+
White / Cool Gray Surface
+
Blue Jump Blue
+
Cyan Accent
+
Talent Color
```

### Background

White 또는 아주 옅은 Cool Blue / Blue Gray 계열을 기본으로 고려합니다.

### Surface

카드와 Panel은 배경보다 약간 분리되는 밝은 Surface를 사용합니다.

### Brand

Blue와 Cyan 계열을 다음 요소에 사용합니다.

- 주요 CTA
- 선택 상태
- Navigation
- Link
- Focus
- Portal
- 공통 강조 요소

### Text

순수 Black보다는 매우 짙은 Navy 또는 Blue Gray 계열을 고려합니다.

### Talent Color

특정 버튜버 Context에서는 해당 버튜버의 대표 색상을 Accent로 사용합니다.

Talent Color가 기본 Brand Color를 완전히 대체하지는 않습니다.

---

# 6. 버튜버별 Theme

각 버튜버 커뮤니티는 동일한 서비스 안의 서로 다른 공간처럼 표현합니다.

예:

```text
Blue Jump Plaza
│
├─ Talent A
│   └─ Talent A Theme
│
├─ Talent B
│   └─ Talent B Theme
│
└─ Talent C
    └─ Talent C Theme
```

Theme 변경 시 다음 요소를 조정할 수 있습니다.

- Hero 배경
- 주요 Accent
- 활성 Navigation
- Button 강조
- Badge 또는 Tag
- Decorative Pattern
- Profile Highlight

반면 다음 요소는 변경하지 않습니다.

- 기본 Layout
- Navigation 위치
- Component 사용법
- Typography 구조
- 콘텐츠 정보 구조

사용자가 다른 버튜버 공간으로 이동하더라도 새로운 사이트를 사용하는 것처럼 느끼지 않도록 합니다.

---

## 6.1 Theme Transition

다른 버튜버의 커뮤니티로 이동할 때 Theme이 즉시 교체되는 대신 짧은 Transition을 적용할 수 있습니다.

예:

```text
Talent A
↓
Talent 변경
↓
Color Transition
↓
Talent B
```

Transition은 짧고 단순하게 유지합니다.

페이지 이동마다 큰 Portal Animation을 반복하지 않습니다.

---

# 7. 형태

기본 Component는 일반적인 웹 UI의 명확한 형태를 유지합니다.

브랜드 표현은 다음 요소를 제한적으로 활용합니다.

- Circle
- Capsule
- Soft Rectangle
- Blob
- Ripple
- Orbit
- Trail

Portal이나 Hero 등 브랜드 표현이 강한 영역에서는 비정형적인 Shape를 사용할 수 있지만 게시글, Form, Navigation 등의 기본 UI는 사용성을 우선합니다.

---

# 8. Portal

Portal은 샘플에서 가장 강하게 브랜드를 표현하는 화면입니다.

메인 페이지 위에 전체 화면 Layer로 표시합니다.

기본 구성은 다음과 같습니다.

```text
Background

        Portal

      BLUE JUMP

 PRESS SPACE TO JUMP
```

모바일에서는 다음과 같이 표현합니다.

```text
TOUCH TO JUMP
```

---

## 8.1 Portal 분위기

Portal 화면은 Main보다 어두운 배경을 사용할 수 있습니다.

예:

```text
Midnight Blue
+
Cyan Portal
+
Soft Glow
+
Particle
```

Main으로 진입하는 순간 밝은 Plaza와 대비되도록 구성합니다.

---

## 8.2 Portal Motion

입력 시 다음과 같은 흐름을 고려합니다.

```text
Input
↓
Portal Compression
↓
Expansion
↓
Ripple / Light
↓
Portal Layer 제거
↓
Main
```

Animation은 짧게 유지합니다.

과도한 화면 흔들림이나 강한 Flash는 사용하지 않습니다.

---

# 9. Main Page

Main Page는 단순한 게시글 Feed가 아니라 여러 활동이 동시에 보이는 **Activity Hub**로 구성합니다.

예:

```text
LIVE
Talent
Recent Community
Creative
Projects
Gatherings
Schedule
Archive
```

화면에 모든 영역을 같은 크기로 배치하지 않고 현재 활동성과 중요도에 따라 시각적 우선순위를 구분합니다.

---

## 9.1 Main의 인상

Main은 다음과 같은 느낌을 목표로 합니다.

> 사람들이 여러 방향으로 이동하고 활동하는 광장

Feed 하나만 길게 이어지는 구조보다 여러 종류의 콘텐츠가 서로 다른 형태로 나타나도록 합니다.

---

# 10. Navigation

Navigation은 화려한 표현보다 서비스 구조를 쉽게 이해하는 것을 우선합니다.

주요 Navigation 후보는 다음과 같습니다.

- Main
- Community
- Creative
- Projects
- Gatherings
- Archive
- Talents

사용자 Profile과 알림 등 개인 기능은 별도의 영역으로 분리할 수 있습니다.

Talent Community에서도 Global Navigation은 유지합니다.

---

# 11. 콘텐츠 카드

모든 콘텐츠를 동일한 카드 모양으로 만들지 않습니다.

콘텐츠의 성격에 따라 다른 형태를 사용합니다.

### Post

텍스트와 작성자를 중심으로 구성합니다.

### Creative

이미지와 콘텐츠 자체를 중심으로 구성합니다.

### Project

현재 상태와 모집 역할을 강조합니다.

### Gathering

날짜, 장소, 참가 인원을 강조합니다.

### Archive

날짜와 기록의 성격을 강조합니다.

한눈에 어떤 종류의 콘텐츠인지 구분할 수 있도록 합니다.

---

# 12. Creative

Creative 영역에서는 UI 장식을 가장 적게 사용합니다.

```text
Content
██████████

Creator
Talent / Type
```

팬아트와 이미지가 중심인 경우 Gallery 형태를 우선 고려합니다.

작품 위에 과도한 Gradient, Badge, Button을 겹치지 않습니다.

상세 정보는 Hover, 선택 또는 상세 화면에서 확인할 수 있도록 합니다.

---

# 13. 팬 프로필

프로필은 일반적인 계정 관리 화면보다 사용자의 팬 활동을 보여 주는 공간으로 구성합니다.

상단에는 `Profile Card`를 배치하는 방향을 고려합니다.

예:

```text
┌────────────────────────────┐
│ BLUE JUMP                  │
│                            │
│ [Avatar]  Nickname         │
│                            │
│ Favorite Talent            │
│                            │
│ Artist  /  Organizer       │
│                            │
│ Projects  3                │
│ Creative  12               │
└────────────────────────────┘
```

실제 디자인에서는 신분증처럼 딱딱하게 만들기보다 디지털 카드와 팬덤 프로필의 중간 정도로 표현합니다.

---

## 13.1 Fan Passport

장기적인 내부 콘셉트로 사용자의 활동이 누적되는 `Fan Passport` 개념을 고려합니다.

프로필에서 다음 활동을 확인할 수 있습니다.

- 활동 유형
- 창작
- 프로젝트
- 관심 버튜버
- 커뮤니티 활동
- 행사 및 모임

다만 Sample에서는 복잡한 Gamification이나 Achievement 시스템으로 확장하지 않습니다.

---

# 14. 활동 유형

활동 유형은 일반적인 Level Badge처럼 표현하지 않습니다.

예:

```text
GOLD
SILVER
BRONZE
```

와 같은 형태는 사용하지 않습니다.

대신 각각 독립적인 **Patch / Pin / Sticker**에 가까운 형태를 고려합니다.

예:

```text
Artist
Musician
Organizer
Archivist
3D Artist
```

각 유형은 서로 다른 Shape 또는 Symbol을 가질 수 있지만 크기와 시각적 중요도는 비슷하게 유지합니다.

이를 통해 등급보다 사용자의 성향을 표현하는 요소로 보이도록 합니다.

---

# 15. 프로젝트

Project Card에서는 게시글보다 구조화된 정보를 강조합니다.

예:

```text
팬송 프로젝트

관련 Talent
○○○

모집
Illustrator
Video Editor

참여
4 / 7

진행 중
```

상태와 모집 역할이 한눈에 보이도록 합니다.

완료된 프로젝트는 결과물을 중심으로 표현할 수 있습니다.

---

# 16. 오프라인 모임

Gathering은 일반 Post보다 Event 또는 Poster에 가까운 형태로 표현합니다.

중요 정보는 다음과 같습니다.

- 날짜
- 장소
- 제목
- 주최자
- 참가 현황

예:

```text
08.29 SAT

○○ 생일카페 같이 가요

서울 홍대
8 / 12명
```

사용자가 목록을 보면서 일반적인 읽을거리와 실제 참여 가능한 활동을 즉시 구분할 수 있도록 합니다.

---

# 17. 팬덤 아카이브

Archive는 실시간 Feed와 다른 인상을 제공합니다.

보다 차분하고 기록 중심적인 UI를 사용합니다.

다음 표현을 고려합니다.

- Timeline
- Index
- Date
- Related Content
- Related Talent

예:

```text
2026.08.12

○○ 밈 최초 등장

관련 방송
관련 게시글
관련 팬아트
```

---

# 18. 감옥 Demo

감옥은 일반 커뮤니티와 의도적으로 다른 분위기를 사용합니다.

일반 UI가 다음과 같다면,

```text
밝음
개방적
움직임
색상
```

감옥은 다음과 같이 대비시킵니다.

```text
저채도
정적
좁은 공간감
제한된 Interaction
```

일부 오래된 Online RPG의 UI를 연상시키는 표현을 가볍게 사용할 수 있습니다.

다만 사용자를 조롱하거나 공개적으로 낙인찍는 표현은 사용하지 않습니다.

---

## 18.1 복귀

복귀 Interaction에서는 다시 Blue / Cyan 계열의 색상이 나타나도록 할 수 있습니다.

```text
죄송합니다 × 3
↓
Restriction 해제
↓
Light / Portal Effect
↓
Main
```

이를 통해 제한된 공간에서 다시 커뮤니티로 돌아오는 전환을 시각적으로 표현합니다.

---

# 19. Motion

Motion은 Decoration이 아니라 UI 상태와 공간 이동을 설명하는 용도로 사용합니다.

공통적인 Motion Language는 `Jump`를 기반으로 합니다.

예:

- Card Hover 시 아주 작은 상승
- Reaction 선택 시 짧은 Bounce
- Talent 변경 시 Color Shift
- Portal 진입 시 Expansion
- 새로운 콘텐츠 등장 시 짧은 Fade / Lift

Motion은 짧고 가볍게 유지합니다.

---

# 20. Typography

Typography는 캐릭터성보다 가독성을 우선합니다.

본문, 게시글, 댓글처럼 읽는 시간이 긴 영역에서는 일반적인 Sans Serif 계열을 사용합니다.

브랜드나 주요 Heading에서는 필요에 따라 조금 더 Character가 있는 Typography를 사용할 수 있습니다.

구분은 다음과 같습니다.

```text
Display
→ Portal / Hero

Heading
→ Page / Section

Body
→ Community Content

Caption
→ Metadata
```

버튜버마다 기본 Font Family를 변경하지는 않습니다.

---

# 21. 아이콘

아이콘은 전체적으로 동일한 Style을 사용합니다.

버튜버별 Theme에서 아이콘 자체를 교체하기보다 색상과 일부 장식 요소만 변경합니다.

활동 유형처럼 의미 자체가 중요한 요소는 별도의 Symbol을 사용할 수 있습니다.

---

# 22. 이미지 사용

버튜버 이미지와 팬 창작물이 많은 서비스이므로 UI 자체가 이미지와 경쟁하지 않도록 합니다.

### Talent

Hero 또는 Profile에서 비교적 크게 사용할 수 있습니다.

### Creative

작품 자체를 최우선으로 표시합니다.

### Community

작성자 Avatar와 필요한 Thumbnail 정도로 제한합니다.

이미지가 없는 콘텐츠도 자연스럽게 보이도록 구성합니다.

---

# 23. Dark Mode

Sample에서는 필수 범위로 두지 않습니다.

추후 적용할 경우 단순히 Black Theme으로 변경하기보다 다음 방향을 고려합니다.

```text
Light
Cloud / Sky

Dark
Deep Ocean / Night Portal
```

Cyan과 Talent Accent가 Dark Surface에서도 자연스럽게 사용되도록 설계합니다.

# 24. Responsive 방향

Desktop, Tablet, Mobile에서 동일한 정보 구조를 유지합니다.

### Desktop

여러 활동을 동시에 볼 수 있는 넓은 Layout을 활용합니다.

### Tablet

Column 수를 줄이고 주요 영역의 우선순위를 유지합니다.

### Mobile

한 번에 하나의 콘텐츠 흐름에 집중하도록 구성합니다.

Desktop에서 Side Panel로 제공되는 정보는 Mobile에서 Section, Drawer 또는 Bottom Sheet 등으로 이동할 수 있습니다.

# 25. 접근성

브랜드 연출 때문에 기본적인 사용성을 희생하지 않습니다.

다음 항목을 고려합니다.

- 충분한 Color Contrast
- Keyboard Navigation
- Focus State
- 의미 있는 Button Label
- 이미지 Alternative Text
- Color 이외의 상태 표현
- `prefers-reduced-motion`
- Touch Target 크기
- Space 이외의 Portal 진입 방법

# 26. 피해야 할 방향

## 과도한 Cyberpunk

Dark Background와 Neon을 화면 전체에 사용하지 않습니다.

블루점프의 Portal 이미지는 활용하되 Cyberpunk 서비스처럼 보이지 않도록 합니다.

---

## 모바일 게임 형태

다음 요소가 중심이 되는 UI를 피합니다.

- Level
- Ranking
- 출석 보상
- VIP
- 과금 강조
- 재화 중심 Navigation

포인트와 활동 유형이 존재하더라도 서비스 전체가 게임 경제처럼 보이지 않도록 합니다.

---

## 모든 화면의 과도한 캐릭터화

각 버튜버의 이미지와 Theme을 반영하되 모든 Component를 캐릭터별로 별도 디자인하지 않습니다.

---

## 지나친 기업 홈페이지 형태

공식 홈페이지처럼 정보 전달만 하는 정적인 화면보다 사용자가 실제로 활동하는 커뮤니티의 느낌을 유지합니다.

---

## 모든 콘텐츠의 동일한 카드화

게시글, 프로젝트, 모임, 창작물 등 서로 다른 콘텐츠를 모두 같은 Card Component처럼 보이게 만들지 않습니다.

---

# 28. UI 판단 기준

화면을 설계하거나 Component를 추가할 때 다음 질문을 기준으로 판단합니다.

### 블루점프 전체 UI와 어울리는가?

Talent Theme이 제거되어도 하나의 서비스처럼 보여야 합니다.

### 해당 버튜버의 공간이라는 것이 느껴지는가?

색상과 일부 Visual만으로도 현재 Context를 구분할 수 있어야 합니다.

### 콘텐츠보다 UI가 먼저 보이지 않는가?

특히 Creative에서는 콘텐츠가 가장 먼저 보여야 합니다.

### 기능의 성격을 한눈에 구분할 수 있는가?

Post, Project, Gathering, Archive가 서로 다른 목적으로 보이는지 확인합니다.

### 놀이성이 사용성을 방해하지 않는가?

Animation과 Decoration은 기능을 이해하는 데 방해가 되지 않아야 합니다.

### 서열을 불필요하게 시각화하고 있지 않은가?

활동 유형, Profile, Point 등의 UI가 Ranking이나 Level처럼 보이지 않는지 확인합니다.

# 29. Sample UI 목표

이번 샘플에서 UI를 통해 다음 내용을 전달하는 것을 목표로 합니다.

- 블루점프라는 하나의 공통 공간이 존재합니다.
- 각 버튜버는 그 안에서 자신만의 공간을 가집니다.
- 팬은 게시글만 작성하는 사용자가 아니라 다양한 형태로 활동할 수 있습니다.
- 팬아트와 프로젝트, 모임, 기록이 서로 연결됩니다.
- 블루점프의 Portal과 `Jump`라는 이미지를 자연스럽게 서비스 경험에 반영합니다.
- 일반적인 팬카페와 다른 방향을 보여 주되 실제 커뮤니티로 사용할 수 있는 익숙한 구조를 유지합니다.

샘플에서는 시각적 독창성 자체보다 **블루점프의 특성과 커뮤니티의 구조가 UI를 통해 자연스럽게 이해되는 것**을 우선합니다.
