# 화면 흐름

## 1. 문서 목적

이 문서는 블루점프 팬 커뮤니티 샘플에서 사용자가 주요 화면을 어떤 순서로 탐색하고 이동하는지를 정의합니다.

샘플은 Frontend와 Mock Data만으로 구성하므로 실제 인증, 데이터 저장, 결제, 운영 기능의 처리 흐름은 다루지 않습니다.

본 문서에서는 다음 내용을 중심으로 정리합니다.

- 전체 화면 구조
- 주요 Navigation 흐름
- Portal 진입
- 메인 페이지 탐색
- 버튜버별 커뮤니티 이동
- 게시글 및 창작물 탐색
- 사용자 프로필 이동
- 프로젝트 및 모임 탐색
- 아카이브 탐색
- 샘플용 Demo Interaction

세부 화면 구성과 UI 배치는 이후 화면 설계 단계에서 정의합니다.

---

# 2. 전체 화면 구조

샘플의 기본 화면 구조는 다음과 같이 구성합니다.

```text
Portal Layer
    │
    ▼
Main
    │
    ├─ Community
    │   ├─ Post List
    │   └─ Post Detail
    │
    ├─ Creative
    │   ├─ Creative List
    │   └─ Creative Detail
    │
    ├─ Projects
    │   ├─ Project List
    │   └─ Project Detail
    │
    ├─ Gatherings
    │   ├─ Gathering List
    │   └─ Gathering Detail
    │
    ├─ Archive
    │   ├─ Archive List
    │   └─ Archive Detail
    │
    ├─ Talents
    │   ├─ Talent List
    │   └─ Talent Community
    │
    └─ Profile
        └─ User Profile
```

각 상세 화면에서는 관련 사용자, 버튜버, 콘텐츠로 다시 이동할 수 있도록 연결합니다.

---

# 3. Portal 진입 흐름

서비스의 기본 진입 경험입니다.

```text
사이트 접속
↓
Main Page 렌더링
+
Portal Layer 표시
↓
사용자 입력 대기
↓
PC
PRESS SPACE TO JUMP

Mobile / Tablet
Touch to Jump
↓
Portal Open Animation
↓
Portal Layer 제거
↓
Main Page
```

## 3.1 PC

다음 입력을 지원합니다.

- Space
- Portal Visual 클릭
- 별도의 바로 진입 UI가 제공되는 경우 해당 UI 선택

Space 입력은 주요 브랜드 Interaction으로 사용하지만 유일한 진입 방법으로 제한하지 않습니다.

---

## 3.2 Mobile / Tablet

화면 또는 Portal 영역 Touch를 통해 진입합니다.

```text
Touch
↓
Portal 반응
↓
Open Animation
↓
Main Page
```

---

## 3.3 Reduced Motion

`prefers-reduced-motion`이 활성화된 경우 Portal Animation을 축소하거나 즉시 Main Page로 전환할 수 있도록 합니다.

---

# 4. 메인 페이지 흐름

Main은 블루점프 커뮤니티의 주요 활동을 탐색하는 시작점입니다.

```text
Main
│
├─ 현재 LIVE
│   └─ Talent Community
│
├─ Talent
│   └─ Talent Community
│
├─ 최근 게시글
│   └─ Post Detail
│
├─ 최근 창작물
│   └─ Creative Detail
│
├─ 진행 중인 프로젝트
│   └─ Project Detail
│
├─ 예정된 모임
│   └─ Gathering Detail
│
└─ 최근 아카이브
    └─ Archive Detail
```

Main에서는 각 콘텐츠의 일부만 보여 주고, 더 많은 콘텐츠를 보고 싶은 경우 해당 영역의 목록 화면으로 이동하도록 합니다.

예:

```text
최근 팬아트
↓
더 보기
↓
Creative List
```

# 5. Navigation 흐름

Global Navigation을 통해 주요 영역으로 직접 이동할 수 있도록 합니다.

```text
Global Navigation

Main
Community
Creative
Projects
Gatherings
Archive
Talents
Profile
```

각 화면에서 주요 Navigation은 유지합니다.

버튜버별 커뮤니티에 진입한 경우 Global Navigation과 Talent Context를 동시에 유지합니다.

```text
Global Navigation
+
현재 Talent
```

예:

```text
BLUE JUMP

Community
Creative
Projects
...

현재 공간
Talent A
```

# 17. 화면 간 주요 연결 관계

샘플에서는 각 기능을 독립된 메뉴로만 만들지 않고 서로 연결된 구조를 보여 주는 것이 중요합니다.

대표적인 연결은 다음과 같습니다.

```text
Post
→ User Profile
→ Creative
→ Talent

Creative
→ Creator Profile
→ Project

Project
→ Participant Profile
→ Creative

Gathering
→ Organizer Profile
→ Talent

Archive
→ Talent
→ Post
→ Creative
```

이를 통해 사용자가 단순히 목록과 상세 화면을 왕복하는 것이 아니라 팬, 콘텐츠, 버튜버, 활동 사이를 자연스럽게 이동할 수 있도록 합니다.

---

# 18. Back Navigation

상세 화면에서 이전 Context로 자연스럽게 돌아갈 수 있도록 합니다.

예:

```text
Talent A Community
↓
Creative
↓
Creative Detail
↓
Back
↓
Talent A Creative
```

단순히 브라우저 History에만 의존하지 않고 Breadcrumb 또는 화면 내 Context 표시를 사용할 수 있습니다.

구체적인 UI 방식은 화면 설계 단계에서 결정합니다.

---

# 19. Desktop 화면 흐름

Desktop에서는 Global Navigation과 콘텐츠 Context를 동시에 확인할 수 있도록 구성하는 방향을 고려합니다.

예:

```text
Global Navigation
│
├─────────────────────────────────────
│
│   Main Content
│
│                         Context Area
│
└─────────────────────────────────────
```

Talent Community에서는 버튜버 관련 Navigation 또는 Theme Context를 추가할 수 있습니다.

---

# 20. Mobile 화면 흐름

Mobile에서도 정보 구조 자체는 Desktop과 동일하게 유지합니다.

다만 Navigation과 부가 정보의 표현 방식은 단순화합니다.

예:

```text
Main
↓
Mobile Navigation
↓
Creative
↓
Creative Detail
↓
Profile
```

Desktop에서 Side 영역에 제공되는 정보는 Mobile에서는 Section 또는 별도 Drawer 등으로 이동할 수 있습니다.

구체적인 Responsive Layout은 화면 설계 단계에서 정의합니다.

---

# 21. 샘플 기본 시연 흐름

블루점프 측에 샘플을 처음 보여 줄 때는 다음 순서로 주요 아이디어를 확인할 수 있도록 구성하는 것을 기본 시나리오로 합니다.

```text
1. 사이트 접속

2. Portal
   PRESS SPACE TO JUMP

3. Main
   블루점프 전체 활동 확인

4. Talent 선택
   버튜버별 Theme 전환 확인

5. Talent Community
   게시글 및 창작물 확인

6. Creative Detail
   창작물 확인

7. Creator Profile
   활동 유형 및 Profile Card 확인

8. Project
   팬 협업 구조 확인

9. Gathering
   오프라인 활동 구조 확인

10. Archive
    팬덤 기록 구조 확인
```

이 흐름만으로도 샘플에서 제안하는 주요 서비스 구조를 한 번에 확인할 수 있도록 합니다.

# 22. 선택 시연 흐름

기본 시연 이후 필요에 따라 다음 기능을 별도로 보여 줄 수 있습니다.

### 감옥

# 23. 화면 흐름 설계 원칙

샘플 화면 흐름은 다음 원칙을 기준으로 합니다.

### 콘텐츠에서 사람으로 이동할 수 있어야 합니다

```text
팬아트
→ 창작자
```

### 사람에서 활동으로 이동할 수 있어야 합니다

```text
프로필
→ 프로젝트
→ 창작물
```

### 콘텐츠에서 버튜버로 이동할 수 있어야 합니다

```text
게시글
→ Talent
```

### 버튜버에서 관련 팬 활동을 탐색할 수 있어야 합니다

```text
Talent
→ Community
→ Creative
→ Project
→ Archive
```

### 모든 기능이 Main으로부터만 시작될 필요는 없습니다

사용자는 서비스 내부의 여러 연결을 통해 자연스럽게 다른 영역으로 이동할 수 있어야 합니다.

# 24. 샘플에서 다루지 않는 흐름

다음 흐름은 실제 MVP 단계에서 별도로 설계합니다.

- 실제 회원가입 및 계정 생성
- 이메일 인증
- 비밀번호 재설정

- 게시글 실제 저장
- 파일 Upload 및 Storage
- Project 실제 신청 및 승인
- Gathering 실제 신청 및 승인
- 신고
- 제재 처리

# 25. 이후 문서와의 관계

본 문서에서는 **어떤 화면에서 어떤 화면으로 이동하는지**를 정의합니다.

다음 단계의 화면 설계에서는 각 화면의 실제 구성을 구체화합니다.

예:

```text
화면 흐름

Main
↓
Project Detail
```

이후 화면 설계:

```text
Project Detail

- Header
- Project Hero
- Talent
- 상태
- 설명
- 모집 역할
- 참여자
- 결과물
- CTA
```

따라서 본 문서에서는 Component의 위치, 크기, Grid, Typography 등의 세부 UI는 확정하지 않습니다.
